How it works

Three steps from download to proof.

  1. 1

    Install

    Run the installer, or build.bat from a checkout. Put mvl on PATH with mvl.bat install-cli.

    mvl hv
  2. 2

    Create

    An unattended install from verified official media to a clean baseline snapshot.

    mvl up proof-1
  3. 3

    Prove

    Build or install on the fresh machine and keep the receipt.

    mvl build proof-1 --repo owner/my-repo

    Guided tasks

    Questions

    Before you download.

    Does it change my PC?

    No change to your sign-in, User Account Control or power state. It writes to its own state folder, %LOCALAPPDATA%\MaterialVmLabs. Installing a hypervisor needs your approval, and its administrator prompt is yours to answer.

    Why is it not code-signed?

    Releases are not code-signed, so Windows SmartScreen may warn. Each release lists the SHA-256 of every file so you can check what you downloaded.

    Has it been tested on real hardware?

    Not fully yet. Real lab machine creation on a Windows host, with VMware and VirtualBox, is still listed under "Not yet verified" in the roadmap, and shipped features have no recorded check from a built release yet. The features page gives the status of each part.

    Which hypervisor does it use?

    VMware Workstation when it is installed and vmrun answers, otherwise VirtualBox. mvl hv says which one and why. See Hypervisors.

    Can my agents use it?

    Yes. Add --json to any command for one compact JSON object; exit codes are 0 done, 1 problem and 2 bad usage. See the CLI reference.

    Why private repositories only for runners?

    A self-hosted runner on a public repository would run code from anyone who opens a pull request. mvl reads the visibility and refuses anything that is not private.

    Get a clean machine in one command.

    A Windows PC with VMware Workstation or VirtualBox. Not code-signed; the SHA-256 of every file is on the release page.
